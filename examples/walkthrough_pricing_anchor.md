# walkthrough — 船货匹配:先锚价,再报价

全程假数据:船名、成交、数字全部虚构(整数示例值,不代表任何真实市场水平)。演示 `pricing-anchor` skill 在一次「给船找货」对话里怎么走,以及一次**错误示范**长什么样。你的领域换成你的标的,形状不变。

## 场景

用户是 operator,手上有一条刚租入的船要找下一票货:

> 「MV EXAMPLE STAR,58k Supramax,2006 年造,{{北亚某港}} 下周三 open。东南亚回中国的煤,现在能做到多少?」

「能做到多少」+ 具体船 → **`pricing-anchor` MUST 触发**。任何数字出口之前先锚价。

---

## ❌ 错误示范(先看这个)

AI 没走 skill,直接答:

> 「当前 {{某 Supramax 指数}} 在 15,000 左右,这条船按指数的 95% 算,大约能做 14,250/day。」

三处错,每一处都是真实会发生的:

1. **没定价格族**:2006 年造 = 老龄族。指数背后的基准船是年轻、能进所有高价生意的船,老龄船被锁在低价子集里,和指数之间是台阶差,不是「打个 95 折」。
2. **指数乘倍数外推**:结构项(准入折价、船位差)不随指数缩放,倍数外推会系统性偏高。
3. **没有一条 peer 成交**:这个数没法被核对。

用户该怎么纠正:「先给我同族的成交锚,不许拿指数乘倍数。」并让它把这条记进 memory。

## ✅ 正确走法

### Step 0 — 定价格族

```
身份卡:MV EXAMPLE STAR · 58k · 2006 · open {{北亚某港}} 下周三 · 无特殊审查资质
族:老龄(18 年以上)× Supramax × 东南亚回程 × $/day 口径
约束:撮合时已排除需要大货主审查的货——定价也按「不过审查」的子市场锚
```

### Step 1 — 锚市场价 level

AI 查成交库,按族筛(同龄族 + 同盆地 + 同交接结构 + 同还交结构,本周优先):

| peer | 规格 / 年份 | 交接 | 还交 | 成交日 | 价 |
|---|---|---|---|---|---|
| MV EXAMPLE PEARL | 56k / 2005 | {{北亚港 A}} | 中国 | 本周二 | 11,500 |
| MV SAMPLE BREEZE | 57k / 2007 | {{北亚港 B}} | 中国 | 本周一 | 12,000 |
| MV DEMO HARBOUR | 55k / 2004 | {{北亚港 A}} | 东南亚 | 上周四 | 10,500 |

读法:

- 第三条还交东南亚(弱需求区),自带贴水,**不和前两条直接比**——剔出主锚,只作参考。
- 前两条本周、同还交结构 → 主锚 **11,500–12,000**。
- 附加项:第二条成交含一笔一次性空放补贴(虚构:+{{X}} 总额),摊到预计航次天数上约 +{{Y}}/day,已计入。headline ≠ all-in。
- 两条都在本周,不需要做时间漂移校正;如果主锚是两周前的,要用**对应细分航线的指数**(不是大盘篮子)标漂移。

### Step 2 — 只调可量化差

```
规格:58k vs peer 56–57k → 多装一点货,货主让利一部分,不全额折算 → +150 [推断,历史观察]
船位:open 港比 peer 交接港远 1.5 天 → 引擎算:1.5 天 × (日租 + 油耗) → −200 [已计算]
```

### Step 3 — 报价

```
族: 老龄 × Supramax × 东南亚回中国 × $/day
锚: peer 11,500–12,000(EXAMPLE PEARL 周二 / SAMPLE BREEZE 周一)
调整: 规格 +150 [推断] · 船位 −200 [已计算,引擎]
→ 谈价区间 11,400–12,000 · 置信 MED 60%
反面: 若本周新增 open 船位多(本周已见 3 条同区老龄船报 open),区间下沿更可能;
      失效位:若同族出现 ≤11,000 的新成交,区间整体下移重锚。
下一步: 按 12,000 开口,底线 11,400。
```

注意输出里有什么:**每个数都能被核对**(peer 列出了船名和日期)、调整项标了是算的还是推断的、有置信度、有反面和失效位、有可执行的下一步。这就是 `rules/EPISTEMICS.md` §9 的 L1 档(锚先行 + 能算就算)。

## 给货找船(反方向)的差异

用户换一个方向问:「这票 50k 煤,东南亚到中国,候选船 A(2019 年)ask 14,000、候选船 B(2005 年)ask 12,500,哪个合理?」

- Step 0 定族按**货**:航线 × 规格段先定族。
- 评审每个候选的 ask,**按它自己的族比 peer**:A 按年轻族锚,B 按老龄族锚。拿年轻族的价去评 B,会觉得 B 很便宜;其实 B 可能只是族内正常价。
- 两个族之间的台阶,就是 operator 在这票货上的 spread 空间——看清它才知道这单赚在哪。

## 这一轮留下了什么

1. 一个可核对的报价(peer + 调整 + 置信 + 失效位)
2. 如果用户纠正了什么(比如「这条航线还交东南亚的贴水比你想的大」)→ 写一条 feedback memory
3. 成交落定后,实际成交价录回成交库——下一次锚价多一个 peer
