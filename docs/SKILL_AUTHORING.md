# SKILL_AUTHORING.md — skill 编写规范

skill = 固化成文件的可复用工作流。写好一个 skill 的判断标准:**三个月后一个全新会话的 AI,靠这份文件能把活干到和你今天一样好。**

## 目录与文件

```
.claude/skills/<skill-name>/
├── SKILL.md              ← 主文件(必须)
├── references/           ← 深度参考资料,按需加载(可选)
└── scripts/              ← 配套脚本(可选)
```

SKILL.md 保持精炼(几百行内);长参考资料放 `references/`,SKILL.md 里指路,用到再读——skill 的加载成本要低,深度按需取。

## frontmatter(决定 skill 能不能被触发)

```yaml
---
name: skill-name
description: 一句话做什么 + 什么时候用。**必须含触发词**:把用户会说的原话模式写进来
  (如「算一下 X / 这个 Y 合理吗 / 帮我整理 Z」),中英文都写。AI 靠 description 匹配
  是否调用本 skill——description 写不好,skill 就是死的。
---
```

## SKILL.md 骨架(五个必备区)

### 1. MUST 触发区

开头明确列出「什么情况必须触发,不可绕过」:

```markdown
## 触发(MUST)
- 用户说「{{原话模式 1}}」「{{原话模式 2}}」
- 用户贴出 {{某种可识别的数据形状,如:带专家换算值的行 / 含成交记录的段落}}
- {{某类动作}}之前(如:任何报价数字出口之前)
```

判据写成**可机械判断的形状**(出现某关键词 / 某数据模式),不写「当合适的时候」。

### 2. 流程步骤

编号步骤,每步可执行、可验证。有顺序依赖就显式写死(如「先盲算,再看专家数——顺序反了就不叫盲测」)。关键步骤给出具体命令 / 代码,不留「你懂的」。

### 3. 禁手清单(踩过的坑)

skill 最值钱的区。每条 = 一次真实踩坑,格式:

```markdown
## 禁手
- ❌ {{错误做法}}({{哪次踩的坑,一句话}})
- ❌ {{错误做法 2}}(…)
```

每次执行本 skill 踩了新坑,**当场回写**进这一区——skill 是活文件,禁手清单越长越值钱。

### 4. 输出契约

规定输出的固定形状(格式模板 / 必含字段 / 简洁度要求),让产物可预期、可核对:

```markdown
## 输出契约
盲算: {{数}} − {{调整项}} = 我的值
专家值 = {{数}} → 偏差 {{x%}} ✓/✗
→ 已录标定点
```

### 5. 关联

链到相邻 skill、上游数据源、下游消费方:「接 [[另一 skill]](关系一句话)」。

## 「skill 建完必接触发点」铁律

一个 skill 建完,**必须**同步做两件事,缺一等于没建:

1. **`rules/skills/INDEX.md` 加一行**——名字 / 一句话 / 触发词,让 AI 查能力时能找到。
2. **高频 / 关键 skill 再挂进 `CLAUDE.md` 硬触发区**——「用户说 X → 必须用 Y skill,不得用普通回答代替」。

两级触发的分工:INDEX 是「AI 主动查」的目录,靠 description 匹配,可能被跳过;CLAUDE.md 硬触发区是「不可绕过」的死规则,每次会话常驻加载。你最在乎的工作流(不容许 AI 用泛泛总结糊弄的那几个)必须上硬触发区;一般 skill 进 INDEX 即可,硬触发区塞满了就失去强制力。

## 反模式

- ❌ description 只写做什么、不写触发词——skill 永远不会被调用
- ❌ 流程写成原则(「仔细检查数据」)而不是步骤(「跑 X 命令,核对 Y 字段」)
- ❌ 禁手清单空着——说明这 skill 还没经过实战,或者踩了坑没回写
- ❌ 建完不接 INDEX / 硬触发区
- ❌ 一个 skill 想覆盖整个领域——一个 skill 管一个工作流,大了就拆
