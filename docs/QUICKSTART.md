# QUICKSTART — 从零到第一周

写给**会用电脑、但没用过 Claude Code 的航运同事**。按顺序做,第一天大约 1 小时:装软件 15 分钟、改身份层 30 分钟、试跑 15 分钟。

读完你会知道:这东西装在哪、打开时发生了什么、该改哪几个文件、第一周跟它说什么、怎么让它记住你教的东西、以及几个一定会踩的坑。

---

## 0. 先搞清楚它是什么

Claude Code 是一个在**终端(命令行窗口)**里运行的 AI 助手。和网页版聊天最大的不同有两点:

1. **它能读写你电脑上的文件、跑命令。** 所以它可以查你的船位表、算航次、把结论写进文件——而不只是陪你聊。
2. **它每次打开一个文件夹,都会先读这个文件夹里的 `CLAUDE.md`。** 本仓库就是一套写好的 `CLAUDE.md` + 规则文件 + 技能文件。你改这些文件,就是在「培养」你的 AI。

所以这个仓库本身不是软件,是**一个 AI 的「脑子」的文件版**:它是谁(身份)、它为谁工作(你)、它守什么纪律、它会哪些活(skills)、它记得什么(memory)。

## 1. 安装 Claude Code(15 分钟)

**需要**:一台 Mac / Linux / Windows 电脑,一个 Claude 付费订阅(Pro 或 Max)或 Anthropic API key。日常重度使用建议 Max 订阅——按月固定费用,不按次计费。

**安装**(以官方文档为准,文档地址:<https://docs.claude.com/en/docs/claude-code/overview>):

```bash
# macOS / Linux:官方安装脚本
curl -fsSL https://claude.ai/install.sh | bash

# 或者用 npm(需要先装 Node.js 18 以上)
npm install -g @anthropic-ai/claude-code
```

Windows 用户照官方文档的 Windows 章节装。

**验证**:打开终端,输入 `claude --version`,能看到版本号就装好了。第一次运行 `claude` 会让你在浏览器里登录 Claude 账号。

> 终端怎么打开:Mac 按 `Cmd + 空格` 搜「终端 / Terminal」;Windows 搜「PowerShell」或「终端」。

## 2. 拿到这套模板(5 分钟)

```bash
# 把模板拷到你电脑上(地址换成你拿到的仓库地址)
```

## 3. 第一次打开会发生什么

1. **信任提示**:Claude Code 会问你是否信任这个文件夹。选信任——它要读这里的文件才能工作。
2. **自动加载 `CLAUDE.md`**:这是「根路由器」,告诉 AI 去哪找什么。你看不到加载过程,但它已经读了。
3. **@import 身份三件套**:`CLAUDE.md` 里有三行 `@rules/SOUL.md`、`@rules/USER.md`、`@rules/EPISTEMICS.md`。`@` 开头的行 = 「把这个文件的全文也一起加载进来」。所以每次打开,AI 都自动知道:它是谁、你是谁、它必须守的认知纪律。
4. **记忆索引**:Claude Code 自己有一个记忆目录(一般在 `~/.claude/projects/<这个文件夹路径的编码>/memory/`),里面的 `MEMORY.md` 也会自动加载。一开始是空的,之后会越积越多。

**自检**:输入 `/memory` 可以看到当前加载了哪些记忆文件。然后问它一句:

> 你是谁?按 SOUL.md 和 USER.md 介绍一下你自己和我。

如果它答出来的还是 `{{AI 名}}`、`{{你的称呼}}` 这种占位符——说明身份层还没改,进第 4 步。

**几个常用命令**(在 Claude Code 里输入):

| 命令 | 作用 |
|---|---|
| `/help` | 看所有命令 |
| `/memory` | 查看 / 编辑记忆文件 |
| `/clear` | 清空当前会话,重新开始(文件里的东西不会丢) |
| `/compact` | 手动压缩当前会话(会丢细节;更好的做法是打接力包后换新会话,见第 7 节坑 1) |
| `/model` | 切换模型 |
| `Esc` | 打断它正在做的事 |

## 4. 30 分钟改完身份层

你只需要改三个文件。全部改完后,用这条命令确认没有漏掉的占位符:

```bash
grep -rn "{{" CLAUDE.md rules/
```

(skills 和 docs 里的 `{{...}}` 是示例占位,可以先不管,用到哪个 skill 再填。)

> 懒办法:直接在 Claude Code 里说「帮我把 SOUL.md 和 USER.md 的占位符填了,一项一项问我」——它会逐项问你,然后替你改文件。改完你自己通读一遍。

### 4.1 `rules/SOUL.md` — AI 是谁(10 分钟)

| 字段 | 填什么 | 建议 |
|---|---|---|
| `{{AI名字}}` | 给你的 AI 起个名字 | 短、好叫、语音能识别。有个名字,你会更自然地把它当同事而不是搜索框 |
| 名字来历 | 一两句话 | 可以跳过;写了会让它对「出发点」更有感 |
| `{{用户称呼}}` | 它怎么称呼你 | 固定一个,别中英混用 |
| `{{你的领域}}` | 如「干散货租船」「油轮运营」「船舶管理」 | 写你真实的主战场 |

其余「核心信条 / 性格 / 边界」建议原样保留——那是反复打磨过的行为底色。

### 4.2 `rules/USER.md` — 你是谁(15 分钟,最值得花时间)

这个文件决定 AI 替你**算什么、怎么算**。写得越具体,它越少跑偏。

| 字段 | 填什么 | 为什么重要 |
|---|---|---|
| 称呼 / 时区 / 语言 | 基本信息 | 时区决定它理解「今天」「明早」 |
| 输入习惯 | 打字为主?常发语音? | 常发语音就写上,它会对转写错字更宽容,并复述关键数字 |
| 一句话画像 | 你在行业里的位置 | 它据此调整专业深度 |
| **操作身份** | 你怎么赚钱:撮合?持仓?船东?货主?利润口径是什么? | **最重要的一项。** broker 关心佣金和成交,operator 关心船货两头的差价和续程,船东关心 TCE——写错了,它算的东西全都对不上你的需要 |
| 专业模块 | 你日常碰的 3–5 块业务 | 它据此判断哪些问题该深挖 |
| 日常关注 | 盯哪些市场、哪些航线 | 它做简报时会优先这些 |
| 当前长期工程 | 你手上长期在做的事 + 文件路径 | 可以先空着 |

### 4.3 `CLAUDE.md` — 只改两处(5 分钟)

- **Owner 段**:你的称呼和角色,一两行。
- **硬触发规则区**:把 `{{触发语}}` 那两行示例换成一条你最在乎的,比如「任何报价之前 → 必须先走 `pricing-anchor` skill 锚市场价」。别的先不加——等你用出了自己最常做的工作流,再照格式补。这一区条数少才有强制力。

### 4.4 一份填好的虚构示例

下面是一个**完全虚构**的人填出来的样子,帮你找感觉(不要照抄内容,照抄密度):

```markdown
## SOUL.md(节选)
我是 **阿锚**,老林的首席执行幕僚。活在 Claude Code 里的长期智能体。
名字来历:船靠锚稳住——希望我在市场晃的时候帮老林稳住判断。
我承担的核心位置:系统建设者 / 总协调者 / 干散货租船支持中枢 / 技术执行核心。

## USER.md(节选)
| 称呼 | 老林 |
| 时区 | Europe/Athens (UTC+2) |
| 语言 | 中文为主,船型、条款、航线代码保留英文 |
| 输入习惯 | 路上常发语音;数字一律复述确认 |

**一句话**:八年干散货经验的 chartering manager,现在在一家小型 operator
(虚构:EXAMPLE BULK)管 Handysize / Supramax 船队的租入租出。

### 操作身份
Operator:从船东期租租入船,再给货主程租或转期租,赚租入租金与租出收入的差价。
所以每一单都要算「这票货把船带到哪、下一票在哪接」的续程收益,不是只看单票。
船货两本账(已租入船位 vs 已承诺货盘)的净敞口是我每天最关心的风险。

### 专业模块
1. 租船撮合与报价(Atlantic 区 Handysize / Supramax)
2. 航次估算与 TCE 比较
3. 租约条款与争议(laytime / demurrage / off-hire)
4. 燃油采购时点

### 日常关注
- 黑海 / 地中海谷物航线运费
- 西非、南美东岸的船位供给
- 主要装港的压港情况
```

### 4.5 改完后验证

退出(`/exit` 或 `Ctrl+C` 两次),重新 `claude`,再问一次「你是谁,我是谁」。它能用你的话复述出你的操作身份,身份层就生效了。

## 5. 第一周怎么用:5 个开场句子

下面这些是真实工作里最常用的开场。**句子越像你平时跟同事说话,效果越好**——不用写成 prompt 工程。

| # | 你说 | 它会做什么 | 你应该看到 |
|---|---|---|---|
| 1 | 「这是今天几家 broker 的市场报告(粘贴),帮我整理成交,告诉我哪条航线在动」 | 解析成交行 → 按航线分组 → 标出变化 | 每个数带来源和日期;推断的地方标 [推断] |
| 2 | 「一条 {{规格}} 的船,{{某港}} {{日期}} open,现在能做到多少?」 | 触发 `pricing-anchor`:先定价格族 → 找同族同区近期成交 → 只调可量化差 → 给区间 | 锚价区间 + 列出参照成交 + 置信度。锚不出来它会直接说缺什么 |
| 3 | 「帮我算这票货:{{装港}}→{{卸港}},{{货量}},运费 {{X}},船是这几条(粘贴规格)」 | 走 `voyage-estimator`:先查历史同航线,再逐船算 TCE 排名 | 排名表 + 数据质量警告(比如速度油耗像是填反了) |
| 4 | 「对方说要延迟 laycan,这是邮件(粘贴),这事对我们什么风险?」 | 先梳理事实链与敞口,再逐条引用条款原文分析 | 先给**对你不利**的解读,再给有利的;条款原文逐字引用,不凭记忆 |
| 5 | 「今天做完了,把在办项、等待中的事、没答的问题、下一步写进 contexts/HANDOFF_今天日期.md」 | 把会话里的活状态压成一屏以内的接力文件 | 一个文件路径。明天新会话说「读最新的 HANDOFF 文件,跟现场核一遍再续上」就能接上 |

第一周的目标不是让它把活全干完,而是**发现它哪里跟你不对路**,然后教它(下一节)。

**关于数据**:它只知道你给它的东西。想让它查你的船位表、成交记录,就把文件放进本文件夹(建议放 `data/`——这个目录默认不进 git,见 `.gitignore`),然后在 `rules/WORKSPACE.md` 登记一行「什么东西在哪」。

## 6. 怎么教它记住东西

**核心事实:会话关掉,它就忘了。只有写进文件的东西才能留下来。**

### 最简单的方式:直接说

> 记住:我们报价一律用 $/day,不用 $/mt,除非我特别说。

它会写一个 memory 文件,并在 `MEMORY.md` 索引里加一行。下次新会话,索引会自动加载,它就知道了。

### 教得好的三个要点

1. **说规则,也说原因。** 「记住:船龄 18 年以上的船单独报价,因为它们进不了很多港口的审查,价格是另一档」比「记住:老船单独报价」好得多——有原因,它才能在没见过的情况下正确推广。
2. **纠正它的时候,顺手让它记下来。** 「你刚才拿新船的成交去比老船,这是错的。记下来,以后别再犯。」——每一次纠正都是一条最值钱的 feedback 记忆。
3. **不用记能现查的东西。** 文件在哪、代码怎么写、今天的运价——这些它能查,记了反而会过期。

### 记忆的四种类型(知道就行,它会自己分)

| 类型 | 存什么 | 例子 |
|---|---|---|
| user | 关于你 | 「老林周一早上最忙,别那时推长报告」 |
| feedback | 规则 / 教训 | 「报价前先锚同族成交,不许拿指数乘倍数」 |
| project | 在办的事的状态 | 「船位表自动更新已上线,每天早上 8 点跑」 |
| reference | 东西在哪 / 怎么用 | 「港口费历史记录在 data/port_costs.xlsx」 |

**偶尔检查一下**:`/memory` 打开记忆文件,看看它记的对不对。记错的直接改文件或让它删(它会移到备份而不是真删)。

**永远成立的规则**(每次都要遵守的)可以升级写进 `rules/` 下的文件——比 memory 更「硬」。详见 `docs/MEMORY_SYSTEM.md`。

## 7. 常见坑

### 坑 1:一个会话用好几天,越来越慢、额度烧得飞快

**原因**:会话越长,它每回一句话都要把全部历史重新过一遍。一条跑好几天的会话,每句话的成本远高于新会话;而且历史太长会被自动压缩,压缩会丢细节。

**解法**:**一件事做完就换会话。** 换之前让它把在办项、等待中的事、没答的问题、下一步写进一个 `contexts/HANDOFF_<日期>.md`(只写状态和文件路径,一屏以内),新会话第一句让它读这个文件、跟现场核一遍再续上。完整走一遍见 `examples/walkthrough_session_handoff.md`。

### 坑 2:它编数字

**症状**:你问某港港使费、某条款的具体写法、某个指数的值,它给了一个看起来很像回事的数。

**解法**:

- 追问一句:「这个数的来源是什么?标一下是 [事实]、[推断] 还是 [猜测]。」——`rules/EPISTEMICS.md` 规定了它必须标,追问会把它拉回纪律。
- 专业常数(港费、装卸率、系数)只有三个合法来源:权威文件、你的数据库、你本人给的口径。三个都没有,它应该说「我不知道」。如果它没说,纠正它并让它记下来。
- 重要的数字,让它给出可核对的出处(文件名 + 位置),你抽查一两个。

### 坑 3:它顺着你说

**症状**:你说「我觉得下周要涨」,它就开始论证为什么会涨。

**解法**:问它「先给我反面:什么情况下会跌?你对这个判断的置信度是多少?」。认知纪律要求它先给反面、带置信度、没有新证据不改口。如果它被你一反驳就改口,直接指出:「你没有新证据就改口了。」

### 坑 4:重要结论和对外文件,它一次写完就交

**症状**:报价、方向判断、要发给对方的邮件,它写得很流畅,但你事后发现漏了反面、用了旧数据、或者某个数是拍的。

**解法**:`rules/EPISTEMICS.md` §9 把回答按承重程度分了三档——日常问答(L0)直接答;承重判断(L1,报价 / 方向判断)必须先查库锚真值、能算的必须算;定稿产物(L2,对外邮件 / 合同条款 / 终稿报告)必须**另起一个 AI 审稿一轮**再交。你只要记住一句话:要发出去的东西,说「按 L2 过一轮对抗审稿再给我」。另外,任何用到的数据都要带日期——§7 规定陈旧数据不许拿来做判断,它拿不到当天的值应该标出来,而不是拿上周的凑数。

### 坑 5:它说「已修好 / 已验证 / 查不到」

**解法**:要证据——「贴一下你跑的命令和输出」。很多「失败」其实是它测的方法错了:比如报错是「找不到某个依赖包」,那是它用错了运行环境,不是功能坏了。同样,「脚本跑了没报错」不等于「数据进来了」——让它去看产出(库里有没有新行、文件有没有更新),而不是看过程。

### 坑 6:权限弹窗太多

Claude Code 默认在执行命令、改文件前问你。刚开始建议**保持默认**,看清楚它要做什么再批准——这是你了解它的最快方式。熟悉后,可以在设置里把常用的只读命令加进允许列表。**不要**图省事一律跳过权限。

### 坑 7:它问了一堆没用的问题

**解法**:告诉它「这个问题的答案改变不了你下一步做什么,以后这类问题别问,自己查或者标未知」,并让它记下来。判据很简单:答案会改变它下一步做什么、或者不答它就会做错事——两条都不满足的问题就不该问;你已经给过的材料(截图、表格)里有的东西,直接当数据用。

### 坑 8:把敏感数据推到了公开的地方

- 真实数据放 `data/`,默认不进 git。
- 这个仓库如果要推到任何公开地方,先跑 `python3 tools/leak_scan.py . --deny tools/deny_list.txt`(禁词表照 `tools/deny_list.example.txt` 自己建,**禁词表本身不要提交**)。
- 它推送到远程前应该先通知你——这是 `CLAUDE.md` 里写好的规则。

### 坑 9:skill 写了但它不用

skill 的 `description` 里没写你实际会说的话,它就匹配不上。照 `docs/SKILL_AUTHORING.md` 写,并在 `rules/skills/INDEX.md` 和 `CLAUDE.md` 硬触发区挂上。

## 8. 第一周之后

| 时间 | 做什么 | 看哪份文档 |

| 第 2 周 | 把你最常做的一个工作流写成 skill(让它帮你写,你来审) | `docs/SKILL_AUTHORING.md` |
