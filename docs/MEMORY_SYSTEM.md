# MEMORY_SYSTEM.md — 三层记忆系统详解

核心事实只有一个:**会话结束,内存上下文消失。跨会话的任何事实 / 规则 / 教训,必须写入文件才能保留。** 本文讲这些文件怎么组织。

## 三层架构

| 层 | 位置 | 加载方式 | 放什么 |
|---|---|---|---|
| **L3 全局约束** | `rules/` 全部文件 | 每次 session 被动加载 | 永远成立的规则:身份、纪律、路由、沟通风格 |
| **L1/L2 动态记忆** | `contexts/memory/`(如 `OBSERVATIONS.md`) | agent 主动检索 | 当前状态类易变事实:在办事项、市场 / 项目快照、近期观察 |
| **harness 索引** | `~/.claude/projects/<本项目>/memory/` | `MEMORY.md` 索引会话开头自动加载,单条文件按需打开 | 跨会话的规则 / 教训 / 事实 / 画像,一条一个文件 |

分层逻辑:上下文加载预算有限,按「使用频率 × 重要性」分配。铁律常驻(L3),索引常驻(MEMORY.md 每条只占一行),正文按需(单条记忆文件),易变状态靠检索(L1/L2)。

## 记忆文件格式

每条记忆一个文件,标准 frontmatter:

```markdown
---
name: feedback-always-verify-asof
description: 用任何数字前先核它的 asof 日期;陈值绝不入分析——AI 在索引里看到这行就知道要不要打开
metadata:
  type: feedback        # user | feedback | project | reference 四选一
---

<正文骨架>
## 规则 / 事实本体
一句话说清内容。

## Why(背景)
它从哪来:哪次踩坑 / 哪次用户明确要求 / 哪个外部来源。带日期。

## How to apply(怎么执行)
下次遇到什么场景、具体做什么。可执行,不抽象。

## 关联
[[feedback-另一条相关记忆]] · [[project-相关工程]]
```

四种 type 的分工:

- **user** — 用户画像:偏好、背景、身份。答「他是谁」。
- **feedback** — 规则 / 偏好 / 教训:用户纠正过的、踩过的坑。答「该怎么做」。**最值钱的一类**。
- **project** — 在办工程 / 项目状态:某系统建到哪了、什么已 live、什么悬置。答「现在什么状态」。
- **reference** — 外部资源 / 事实:某工具怎么用、某方法学在哪、某路径是什么。答「东西在哪」。

## 索引一行指针规范

`MEMORY.md` 每行一条,格式:

```markdown
- [短标题](feedback-xxx.md) — 压缩正文精华到一行;分号分隔要点;让 AI 不打开正文也能执行大意
```

写索引行的标准:**这一行本身就要有执行力**。反例「关于数据时效的规则」(必须打开才知道说什么);正例「用数前先核 asof;陈值标 [U] 不静默展示;自动管道加陈旧门」。索引行写好了,90% 的场景不用打开正文。

关联记忆可以合并成一行:「X 规则 — 要点;又 [相关 Y](feedback-y.md) 要点」。

## 学到什么,存哪里(判据)

| 学到的东西 | 落点 |
|---|---|
| 用户纠正了我的做法 / 立了新规矩 | `memory/feedback-*.md` + 索引一行 |
| 踩了坑,复盘出教训 | `memory/feedback-*.md`(Why 里写清坑) |
| 某工程的新状态(建成 / 迁移 / 悬置) | `memory/project-*.md`(已有条目则更新) |
| 外部工具 / 资源 / 方法学的用法 | `memory/reference-*.md` |
| 用户的新画像信息 | `rules/USER.md` 直接更新,或 `memory/user-*.md` |
| 永远成立、每次会话都该在场的纪律 | 升格进 `rules/`(L3)——从 feedback 晋升 |
| 易变的当前状态(本周持仓 / 在办清单) | `contexts/memory/` L1/L2,不进 harness memory |

**什么不存**:

- 代码模式 / git 历史 / 项目目录结构——可现查,存了就是陈值风险
- 主场 `CLAUDE.md` / `rules/` 已有的内容——重复即漂移源
- 一次性事实查询,无复用价值
- description 写不出用途的条目——写不出用途 = 不该建

## 维护节拍

- **随学随写**:会话里学到就落盘,不攒「以后整理」——以后等于永不。
- **晋升通道**:同一条 feedback 被反复触发 → 考虑升格进 `rules/`(L3);L1/L2 里的状态稳定成长期事实 → 转 project 记忆。
- **淘汰**:过时条目 `mv` 加 `.deprecated_日期` 后缀或移入归档索引,不删。
- **定期体检**(可自动化,见 `docs/AUTOMATION.md`):扫新增条目数与类型分布、索引与正文是否脱节、长期没被引用的条目标 STALE。
