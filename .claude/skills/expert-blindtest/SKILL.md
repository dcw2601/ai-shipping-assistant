# expert-blindtest — 专家换算值盲测复算

**每一条带专家换算值的数据,都是一次免费校准。铁律:先盲算,再看专家数——顺序反了就不叫盲测。**

(蒸馏自 dry bulk fixture 换算值盲测实战。通用于任何「外部专家 / 权威源给出了一个你自己也有引擎能算的数」的领域:估值、换算、评级、定价均适用。)

## 为什么这个循环值钱

专家数直接抄 = 你的引擎永远不进步,而且专家也会错。先盲算再对比,三种结果都有收益:偏差带内 → 引擎可信度 +1;偏差超阈且是你错 → 排查出一条新规则;偏差超阈且是专家错 → 你抓到了一个别人没抓到的信号。**长期积累的标定点 = 回归系数越来越准的原料。**

## 触发(MUST,自动)

用户贴的数据行里出现**换算值标注**:

- `(xxx eqv)` / `equivalent xxx` / `≈ {{基准码}} xxx` / {{你领域的换算值写法}}
- 专家整表(批量换算值)→ 批量录入路径;单条 → 走本 skill

## 流程

1. **解析**:标的参数 / 原始值 / 专家换算值 + 基准码 / **特殊机制标记**(如回溯生效、特殊条款——它们会改变换算逻辑,见「已淬炼规则」)。语音 / 口述输入按对照表还原(「P六」= P6 类)。
2. **盲算**(先于看专家数):调你的引擎,输入标的参数,得出你的换算值。参数缺失 → **只录点不盲算**,标缺口,补数后回补。
   ```bash
   python3 tools/{{your_engine}}/blindtest.py \
     --subject "{{标的}}" --raw-value {{原始值}} --route {{基准码}} \
     --expert-equiv {{专家值}}    # 专家值仅用于最后对比,引擎不可见
   ```
3. **对比 + 归因分层**:输出 `原始值 − 位置项 ± 标的因子 = 我的换算值` vs 专家值;偏差 ≤5% = 带内 ✓。归因要分层(位置 / 标的规格 / 口径),不许一个笼统差值糊过去。
4. **录标定点**:自动进标定库(`data/{{calib}}.db`,source 标「专家值 + 我的盲测值 + 日期」)。回归样本自动增长,定期重跑回归系数。
5. **>5% 偏差 → 排查,不硬调**。按序核:
   ① 特殊机制(回溯 / 时效 / 非标条款)是否漏判
   ② 输入数据可信度(对方自报的参数水分)
   ③ 你的引擎口径(费率 / 距离 / 基准卡是否陈旧)
   ④ 专家自己错了(也有的)
   **结构性发现 → 固化成引擎规则;单点噪声 → 只留记录。** 禁止为了对齐这一条硬调系数——那是把引擎调成复读机。
