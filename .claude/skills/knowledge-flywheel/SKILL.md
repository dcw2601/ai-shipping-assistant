# knowledge-flywheel — 知识积累飞轮

**目标:领域知识「越用越厚」。每次接触新知识 / 踩坑 / 复盘,至少留下一个可复用工件——哪怕只是一句话的 memory 指针。微小进步累积 > 完美计划。**

## 触发(任一命中即启动)

| 场景 | 例 |
|---|---|
| 外部知识抓回(检索 / 文章 / 权威公告) | 行业方法学、新规则、价格机制 |
| 专家材料里出现新概念 / 术语 | 报告里一个你没见过的说法 |
| 用户显式给材料 | 「把这份看了沉淀一下」 |
| 推到无解问题(缺背景知识) | 答不上来 → 补知识 → 顺手沉淀 |
| 复盘出教训 | 某次判断错了——「错在哪 + 下次怎么做」 |
| 同一问题第二次出现 | 重复 = 信号,该有持久化笔记了 |

不触发:(a) 一次性事实查询无复用价值 (b) 已有相同笔记 (c) 与领域无关的琐事。

## 四步循环

```
①触发 → ②取源提炼 → ③产出工件 → ④精炼固化
   ↑                                    ↓
   ←—————————— 下一轮起点 ———————————————
```

1. **触发**:识别一个微小可验证的子问题。不追求「全面掌握」,一次只解决一个(如「X 指数怎么算」)。
2. **取源提炼**:先查已有 KB 是否覆盖 → 外部源看目录不全读(`grep -nE '^#{1,2} '` 拉章节,按相关性读段)→ 提炼**操作必备**的 3–5 条可直接套用的结论,不是百科摘抄。
3. **产出工件**(每次触发至少 1 个):

| 工件 | 落点 | 何时建 |
|---|---|---|
| 完整精炼笔记 | KB / vault `{{knowledge}}/<domain>/<topic>.md` | 长篇知识首次入库 |
| 速查卡(操作必备摘录 + 回链原文) | KB `reference/<topic>_card.md` | 高频调用的知识 |
| memory 指针 | `memory/reference-<topic>.md` + MEMORY.md 一行 | 任何未来会话该知道的 |
| 教训 | `memory/feedback-<topic>.md` + 索引行 | 错过一次、想以后不犯 |

4. **精炼固化**:新工件双向链入现有网络(`[[既有卡]]`);旧卡过时 → mv 加 `.deprecated_日期` 后缀(不删);内容厚了 → 拆卡再链回总卡。

## 半自动模式(可选,配合 docs/AUTOMATION.md)

- **每日蒸馏(机器)**:定时脚本(本地小模型即可)扫过去 24h 的产物 / 新材料 → 蒸出「可能长期有价值」的候选 → 追加 `contexts/knowledge_inbox/INBOX.md`,状态 PENDING。**只起草,绝不直接写可信层;没料就输出空,不凑数。**
- **定期晋升(AI 提炼 + 人确认)**:AI 把 PENDING 原料提炼成成品级草稿(一句话说清「是什么 + 落哪 + 为什么留」,五秒看不懂的不上浮)。分级自治:**低风险直接落**(新指针 / 补索引 / 修陈旧)+ 当轮报告可否决;**承重项**(进 rules、改判断锚点)给选项 + 推荐,**用户确认才落**。
- **provenance 隔离**:机器蒸馏的内容晋升时保留来源标注(蒸馏批次 / 日期),与用户亲口给的事实、AI 分析的推断可区分——禁止蒸馏内容洗掉出处冒充一手信息。

## 反模式

- ❌ 「等以后整理」——等于不整理,当场沉淀
- ❌ 把百科条目搬进速查卡——只放操作必备 takeaways,原文回链
- ❌ 一次想覆盖整个域——一次一个子问题
- ❌ memory 写空话——description 看不出用途的条目不该建
- ❌ deprecate 用 rm——一律 mv 改后缀

接 `docs/MEMORY_SYSTEM.md`(落点判据)、`docs/AUTOMATION.md`(蒸馏定时化)。
